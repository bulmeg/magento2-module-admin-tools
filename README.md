# Bulmeg_AdminTools

Админ инструменти за Magento 2: **търсене по телефон**, **цветни статуси** и
**история на клиента в поръчката**. Всеки инструмент се включва и изключва
отделно.

Модулът обединява и замества `Bulmeg_SearchByPhone` и `Bulmeg_AdminStatusColor`.

| | |
|---|---|
| Magento | Open Source / Adobe Commerce 2.4.4 до 2.4.8 (проверен на 2.4.7) |
| PHP | 8.1 до 8.4 |
| Зависи от | `Bulmeg_Core` (менюто BULMEG) |
| Промени в базата | само индекс по `customer_email` в `sales_order`; модулът няма свои таблици |

## Какво прави

### 1. Търсене по телефон (Продажби → Поръчки)

- Колона **„Телефон“** със собствен филтър в списъка с поръчки.
- Номерът се сравнява по цифрите: `0888 123 456`, `0888-123-456`,
  `+359 888 123 456` и `00359888123456` са един и същ номер. Кодът на страната
  (по подразбиране 359) се задава в настройките.
- Главното поле за търсене намира поръчки по телефон, когато въведеното е
  телефон: започва с `0`, `00` или `+` или е изписано с интервали/тирета
  (`0888123456`, `+359 888 123 456`, `888 123 456`). Всичко останало (номер на
  поръчка `000154321` или `100154321`, име, имейл) се търси стандартно.

### 2. Цветни статуси (Продажби → Поръчки)

Колоната **„Статус“** се оцветява според статуса. Цветовете се избират в
настройките от фиксирана палитра (бял, сив, син, зелен, жълт, оранжев, червен,
лилав), като могат да се добавят и собствени статуси. Статус без цвят се показва
както обикновено.

| статус | цвят по подразбиране |
|---|---|
| В очакване (`pending`) | бял |
| Очаква плащане, Преглед на плащането | жълт |
| В обработка (`processing`) | син |
| Задържана (`holded`) | оранжев |
| Завършена (`complete`) | зелен |
| Затворена (`closed`) | сив |
| Отказана (`canceled`) | червен |
| Съмнение за измама (`fraud`) | лилав |

### 3. История на клиента (страницата на поръчката)

При отваряне на поръчка служителят веднага вижда дали клиентът е поръчвал и
преди:

- **горе, в „Информация за акаунта“:** оценка на клиента и брой други поръчки;
  броят е връзка, която отваря раздела по-долу;
- **в лявата колона на поръчката, след „Информация“:** раздел „История на
  поръчките на клиента“ със списък на другите поръчки (дата, клиент, статус,
  сума, оценка, по какво е разпознат) и връзка към всяка от тях. Разделът не
  се показва, когато историята е изключена или служителят няма правото за нея.

Клиентът се разпознава по **акаунт**, **имейл** (без значение от главни/малки
букви) и **телефон** (същият номер, без значение как е изписан, на фактуриране
или доставка); всяко по отделно може да се изключи. Така се намират и
поръчките като гост.

| оценка | кога | цвят |
|---|---|---|
| **Нов клиент** | няма други поръчки | сив |
| **Редовен клиент** | има успешни поръчки и нито една проблемна. Подсказка: може да се предложи отстъпка | зелен |
| **Стар клиент с проблемни поръчки** | има и успешни, и проблемни | оранжев |
| **Стар клиент, но ненадежден** | има други поръчки, но нито една успешна | червен |
| **Повторен клиент** | има други поръчки, без проблемни, но още без достатъчно успешни | син |

**Успешни** са поръчките в статусите от настройката „Статуси на успешна поръчка“
(по подразбиране *В обработка* и *Завършена*). Всеки друг статус е **проблемен**,
освен ако не е в „Статуси, които не се броят“. По подразбиране там е
*В очакване*: поръчки, които чакат друг ден за доставка или доставка на
продукт; те се показват в списъка, но не правят клиента нито редовен, нито
ненадежден.

Показва се и общата сума на успешните поръчки (по валути, ако са в различни,
напр. лева и евро) и разбивка на проблемните по статус.

## Настройки

**Магазини → Конфигурация → Bulmeg → Админ инструменти**, или от менюто
**BULMEG → Админ инструменти → Настройки**.

| група | настройка | по подразбиране |
|---|---|---|
| Търсене по телефон | Включи търсенето по телефон | Да |
| | Търсене на телефон и от главното поле за търсене | Да |
| | Телефонен код на страната | 359 |
| Цветни статуси | Включи цветните статуси | Да |
| | Цветове (статус → цвят) | виж таблицата горе |
| История на клиента | Включи историята на клиента | Да |
| | Разпознаване по акаунт / имейл / телефон | Да / Да / Да |
| | Статуси на успешна поръчка | В обработка, Завършена |
| | Статуси, които не се броят | В очакване |
| | Редовен клиент от (брой успешни поръчки) | 1 |
| | Брой показани поръчки (от 1 до 100) | 20 |
| | Игнорирани имейли и телефони | (няма) |

Настройките са глобални (само „По подразбиране“), защото описват админа, а не
витрината.

**Игнорирани имейли и телефони:** по един на ред: имейл, телефон или цял
домейн като `@example.com` (за имейлите, които магазинът създава сам при
поръчки по телефон). Служебни данни (такива имейли, телефонът на самия магазин)
иначе биха свързали различни клиенти. Ако едно съвпадение доведе над 1000 поръчки,
историята показва предупреждение да се добави стойността тук.

## Права (ACL)

| ресурс | за какво |
|---|---|
| `Bulmeg_AdminTools::config` | Магазини → Настройки → Конфигурация → „Bulmeg: Настройки на Админ инструменти“ |
| `Bulmeg_AdminTools::customer_history` | Продажби → Поръчки → Действия → Преглед → „Bulmeg: История на поръчките на клиента“ |

Администраторите имат всичко. За ограничените роли правото за историята трябва
да се даде изрично (Система → Потребителски роли). Колоната „Телефон“ се вижда от
всеки, който има достъп до списъка с поръчки, както имейлът и адресите в него.

В Adobe Commerce ограниченията на ролите по уебсайт (Admin GWS) не се прилагат
към историята: служител, ограничен до един уебсайт, ще вижда в нея и поръчки от
другите.

## Инсталация

Изисква `Bulmeg_Core`. С Composer:

```bash
composer require bulmeg/module-admin-tools
```

или ръчно в `app/code/Bulmeg/AdminTools`. След това:

```bash
php bin/magento module:enable Bulmeg_AdminTools
php bin/magento setup:upgrade
php bin/magento setup:di:compile                 # в production режим
php bin/magento setup:static-content:deploy -f --area adminhtml bg_BG en_US   # в production режим
php bin/magento cache:flush
```

### Преминаване от старите модули

`Bulmeg_SearchByPhone` и `Bulmeg_AdminStatusColor` се заменят изцяло. Изключете
и премахнете ги **преди** включването на този модул:

```bash
php bin/magento module:disable Bulmeg_SearchByPhone Bulmeg_AdminStatusColor
rm -rf app/code/Bulmeg/SearchByPhone app/code/Bulmeg/AdminStatusColor   # ако са в app/code
php bin/magento setup:upgrade
```

Ако останат включени, нищо не се чупи (полетата са с различни имена), но в
списъка с поръчки ще има две колони „Телефон“; страницата с настройки показва
предупреждение, докато са включени. Старите настройки (`bulmeg_search/*`) не се
пренасят; новите са включени по подразбиране.

## Безопасност

- **Само четене.** Нищо не се записва в поръчките и модулът няма собствени
  таблици. Единствената промяна в базата е индекс по `customer_email` в
  `sales_order` (`setup:upgrade` го добавя онлайн, без да спира поръчките; при
  премахване на модула индексът се маха).
- **Без пренаписване на ядрото.** Няма `preference`. Колоната „Статус“ в списъка
  с поръчки получава собствен клас, наследник на стандартния, който сменя само
  JS компонента, и то само когато цветовете са включени. Има два плъгина, само в
  админа: върху колекцията на списъка с поръчки и върху пълнотекстовия филтър
  (той се намесва само в списъка с поръчки и само когато търсеното е телефон).
- **Изключено = все едно го няма.** Изключеният инструмент не добавя колона,
  филтър, заявка или скрипт, нито колона в износа. Филтър по телефон, останал в
  запазен изглед на списъка, просто се пренебрегва.
- **Масови действия.** При масово действие върху поръчките („Избери всички“)
  телефоните не се зареждат.
- **Грешка не чупи страницата.** Ако историята не може да се зареди, грешката
  се записва в `var/log/exception.log`, а поръчката се показва както обикновено.
  Заявките на историята са с параметри, затова имейли и телефони не попадат в
  лога.
- **Скорост.** Историята търси по индекс за акаунт и имейл. По телефон прави едно
  бързо преминаване през адресите и сравнява номерата точно: около 25 ms при
  30 000 поръчки и около 0,25 s при 300 000. На признак се взимат най-много
  1000 поръчки.
- **Изход и CSP.** Всичко, което се показва, е екранирано; няма вграден
  JavaScript и стилове (съвместимо с Content Security Policy). Цветовете идват
  от фиксирана палитра; въведен от потребител цвят никога не стига до HTML/CSS.
- **Права.** Историята се показва само на служители с правото за нея.

## Как работи

```
etc/adminhtml/system.xml                     настройки (раздел Bulmeg → Админ инструменти)
etc/adminhtml/menu.xml                       BULMEG → Админ инструменти → Настройки
etc/acl.xml                                  правата
etc/adminhtml/di.xml                         двата плъгина
etc/db_schema.xml                            индексът по имейл в sales_order

Plugin/OrderGrid/PhoneColumnPlugin           филтърът „Телефон“ → условие по номер на поръчка;
                                             телефоните на заредената страница с една заявка
Plugin/OrderGrid/KeywordSearchPlugin         главното търсене: телефон → поръчките с този телефон
Model/Phone/Normalizer                       телефон → значещи цифри (без кода на страната)
Model/ResourceModel/OrderPhone               заявките по телефон
Ui/Component/Listing/Column/Telephone        колоната; махната с филтъра, когато е изключено
Ui/Component/Listing/Column/OrderStatus      включва цветния компонент само когато е включено
view/adminhtml/web/js/grid/columns/status.js разширява стандартната колона на Magento

Model/CustomerHistory/HistoryProvider        намира другите поръчки и ги оценява
Model/CustomerHistory/Classifier             оценката (нов / редовен / ненадежден …)
Model/ResourceModel/CustomerOrders           заявките за историята
ViewModel/CustomerHistory                    данните за шаблоните
ViewModel/CustomerHistoryFormatter           текстове, дати и суми (във валутата на поръчката)
view/adminhtml/templates/order/view/*.phtml  редът в „Акаунт“ и разделът с поръчките
```

Колоната „Телефон“ не прави JOIN към адресите в основната заявка на списъка:
подредбата, страниците, другите филтри и износът (CSV/XML) работят точно както в
Magento, а телефонът се включва и в износа.

## Премахване

```bash
php bin/magento module:disable Bulmeg_AdminTools
php bin/magento setup:upgrade
```

`setup:upgrade` маха и индекса по имейл. В базата остават само настройките
(`core_config_data`, пътища `bulmeg_admintools/*`); могат да се изтрият, но не
пречат.
